# geo-lab

**AI 답변에서 브랜드가 어떻게 다뤄지는지를 신뢰구간과 함께 실측한다.**

GEO(Generative Engine Optimization, 생성형 검색엔진 최적화) 업계가 내놓는 수치 대부분은 프롬프트를 **한 번 실행한 결과**다. 그런데 LLM은 비결정적이라 같은 질문에도 매번 다르게 답한다.

> 관측 1회는 측정이 아니라 동전 던지기에 가깝다.

이 저장소는 반대로 한다 — **반복 측정하고, 분포를 보고, 신뢰구간을 붙인다.** 신뢰구간 없는 수치는 여기서 결론으로 쓰지 않는다.

## 조사에서 나온 것 셋

**① GEO는 하나의 사건이 아니다**

`닿는가 → 선택되는가 → 흡수되는가` 세 단계이고, 단계마다 통하는 수단이 다르다. 특히 **출처로 인용되는 것**과 **답변 내용에 실제로 반영되는 것**은 별개다. 출처 목록에 이름만 걸리고 내용은 하나도 안 들어가는 경우가 실재한다.

**② 널리 인용되는 근거에 유효기간이 있다**

GEO 분야에서 가장 많이 인용되는 프린스턴 계열 연구(KDD 2024)는 **GPT-3.5-turbo · 구글 검색 결과 5개 · 단일 턴** 조건의 2023년 11월 실험이다. 그 수치를 현재값으로 인용하면 근거를 넘어선 주장이 된다. 현행 환경에서 재현되는지는 **직접 재봐야** 알 수 있다.

**③ 측정이 무너져 있다**

신뢰구간을 계산하려면 30표본 규모가 필요하고, 예산을 방어하려면 95% 신뢰수준이 필요하다. 그런데 신뢰구간을 보고하는 도구가 드물다. 게다가 플랫폼마다 응답당 인용 개수가 약 6배 차이 나서(Gemini 40~43개 vs SearchGPT 6~7개), **플랫폼을 합산한 단일 점수는 구성비에 좌우된다.**

## 표기 규칙

이 저장소의 존재 이유가 정직한 측정이라, 표기 규칙이 곧 제품 규격이다.

1. 출처 없는 숫자를 쓰지 않는다
2. 상관과 인과를 섞지 않는다. 상관이면 상관이라고 쓴다
3. 측정 조건을 함께 적는다 — 어느 모델, 몇 회 반복, 언제
4. 직접 측정한 것과 인용한 것을 구분한다
5. **한계를 먼저 적는다.** 무엇을 측정하지 못했는지 명시한다

`research/` 문서의 마지막 절은 항상 "이 조사가 답하지 못한 것"이다.
