## 무엇을 버렸나

조사와 구현 중에 검토했다가 접은 것들입니다. **접은 이유가 이 저장소의 판단 기준을 보여줍니다.**

| | 무엇을 버렸나 | 어떤 판단에서 |
|---|---|---|
| `D1` | "조사하면서 바로 깔끔하게 쓰기". 빠르지만 쓰는 사람이 확신하는 것과 검증된 것이 섞인다 | 조사를 인박스에 먼저 덤프하고, 판정을 거쳐 승격했다 |
| `D2` | 권위 있는 학술 출처를 근거로 그대로 쓰는 것. 가장 쉽고 가장 설득력 있어 보이는 선택지였다 | 널리 인용되는 GEO 연구의 수치를 현재값으로 쓰지 않기로 했다 |
| `D3` | 한쪽을 택해 다른 쪽을 기각하는 것. 그리고 "둘 다 중요합니다"로 얼버무리는 것 | 출처 충돌을 "상충"이 아니라 "순서"로 판정했다 |
| `D4` | 가장 인용하기 좋은 형태. 인과로 쓰면 문장이 훨씬 강해진다 | Ahrefs 수치를 상관으로만 쓴다 |
| `D5` | 12종의 기능 목록. 표를 채우면 조사가 풍부해 보인다 | 검증하지 않은 도구 정보를 덤프에서 삭제했다 |
| `D6` | 지금 이걸 빈자리로 선언하는 것 | "틀린 인용을 재는 도구가 없다"를 아직 주장하지 않는다 |
| `D7` | 과정 문서를 폴더로 분리해 체계적으로 보이게 하는 것 | 저장소 구조를 얇게 유지한다 |
| `D8` | 제품 차별점으로 쓰려던 축 하나. 답안에서 가장 강하게 쓸 수 있는 카드였다 | 내 가설이 기각됐다 — "정확성 감지는 빈자리"는 틀렸다 |
| `D9` | "이 문제를 아무도 안 짚는다" 계열의 서술 전부. 답안에서 가장 강하게 들리는 도입부였다 | 이 저장소의 핵심 논지에 선행 연구가 있다 — 자기 서술을 바꿨다 |
| `D10` | 이 수치를 "AI에 노출되려면 무엇을 해야 하나"의 근거로 쓰는 것 | Ahrefs 판정을 한 단계 더 좁혔다 (D4 보강) |
| `D11` | "정확성 감지에도 신뢰구간이 없다"는 서술. 기준 2를 강화하는 데 쓸 수 있는 카드였다 | "도구들이 안 한다"와 "공개하지 않아 알 수 없다"를 구분했다 |
| `D12` | 정정 내용만 반영하고 틀렸던 기록은 지우는 것. 문서가 깔끔해진다 | 회사 사실을 별도 문서로 분리하고, 초기 조사의 오류를 정정 기록으로 남겼다 |
| `D13` | 전술을 모아 목록으로 만드는 것. 가장 실용적으로 보이고 답안에서 표로 만들기 좋다 | 처방에 근거 등급을 매기고, 등급 없는 것은 싣지 않기로 했다 |
| `D14` | 답안에서 "이렇게 하세요" 목록에 이 둘을 넣는 것. 독자 대부분이 기대하는 항목이라 빼면 허전해 보인다 | 가장 널리 퍼진 처방 둘이 가시성 근거가 없음을 확인했다 |
| `D15` | "흡수가 잘 되는 페이지의 특성"을 개선 처방으로 쓰는 것 | 흡수 논문을 프레임으로만 쓰고 인과 근거로는 쓰지 않는다 |
| `D16` | 초안의 기준 3 "믿을 수 있게 재는가". 이미 써둔 것이라 그대로 가는 편이 빨랐다 | 문항1의 기준 3가지를 확정했다 — 세 번째를 "확인 가능성"으로 잡는다 |
| `D17` | 기능 하나를 빌더 연계(진단 → 처방 → 큐샵 적용)로 설계하는 안. 차별성이 가장 크고 회사 입장에서 매력적으로 읽힌다 | PRD에서 스퀘어스 자산을 별도 절로 분리한다 |
| `D18` | "실패는 어차피 제외되니 괜찮다"는 판단. 실제로 이 저장소는 실패 제외를 편향 방지 장치로 설계했으므로 그렇게 넘어가기 쉬웠다 | 실패 제외 규칙이 거꾸로 편향을 만들 뻔했다 — 연결 확인에서 잡았다 |

각 항목의 상세한 이유는 [`docs/DECISIONS.md`](../docs/DECISIONS.md)에 있습니다.
